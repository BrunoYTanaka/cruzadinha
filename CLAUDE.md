# CLAUDE.md

Guidance for Claude Code in this repository.

## Where things stand

"Cruzadinha" is driven by a [GitHub Spec Kit](https://github.com/github/spec-kit) scaffold (v1.0.13, Claude integration, `sh` scripts, sequential numbering). Features 001 to 063 are built; reasoning, findings and tests of each are in `specs/NNN-*/`, history in git and `CHANGELOG.md`. Only the rules a new change can break are kept here; read the feature's spec for the rest.

**Product**
- Crossword site with four sources (`oglobo`, `cruzadaonline`, `cruzadasbrasil`, `clube`; `puzzleSourceNames` in `shared`, lists derive from `puzzleSourceIdSchema.options`). Anyone with the URL plays as a guest; accounts add server-saved progress. O Globo API details: `specs/001-viabilidade-fonte/decision.md`.
- Guest progress, clock, helps, completion and record live only in IndexedDB (`idb`, `cruzadinha-visitante`, `features/guest/`); guest and account data never mix. A `game` generation on the record stops a tab opened before "Jogar de novo" from overwriting the reset.
- User settings are one record (`settingsSchema` in `shared`): device `cruzadinha:settings`, accounts `user_settings` via `GET`/`PUT /api/settings` (newest `savedAt` wins; after login the account wins). New settings fields are optional in the `PUT` body so an older site is accepted.

**API (`apps/api`)**
- Auth: sign-up is behind `REGISTRATION_ENABLED` (default `false`; closed answers `403 registration-closed` first), stores `pending_registrations` and e-mails a link; the password is chosen at `verify-email`. `forgot-password`/`reset-password` work with sign-up closed and end every session of the user. Every e-mail route answers `202 { retryAfter }` the same with or without an account; `429` only per address. E-mail is behind `EmailSender` (`modules/email/`); no `RESEND_API_KEY` in production → `503 email-unavailable`. Tests use `signUpForTest` (`apps/api/src/test/app.ts`) or the CLI. Sessions are server-side (sliding 30 days, 1-year limit), tokens stored as SHA-256. Data: `docs/data-definitions/DDE-005-*`, ERD-005.
- Rate limits live in `rate_limit_attempts`. Use `rateLimiter.reserve` (or `admitAddress`), never `check` then record (`record` is gone). `reserve` does not prune: `auth cleanup` deletes attempts older than 2 days.
- Puzzles: one row per source, level and date; public part and solution in separate `jsonb` columns. `GET /api/puzzles[/:id]` return `{ puzzleId, puzzle, solution }` after revalidating the pair (mismatch → generic 500). A missing past date is fetched from the source behind the persisted per-address `PUZZLE_FETCH` limit, only within 366 days (`FETCH_WINDOW_DAYS`). `createOptionalSession` routes serve guests; an invalid cookie answers `401` and clears it. Sources with `onDemand: false` (`clube`) are collected newest-first via `listRecent`, never fetched from `getByDate`. `GET /api/library` never selects `data`, `solution` or `cells` and never reaches the source.
- Progress: key `(user_id, puzzle_id)`, user always from the session; the server checks only the letter format, the site decides completion. Pure rules `decideSave`/`decideReset`/`decideImport`. Writes count per user (`PROGRESS_SAVE`, 1800/h) and answer `429`.
- Sources: one folder per adapter under `sources/`, no adapter imports another (shared code in `sources/common/`). Real-source findings: `specs/003-*`, `014-*`, `029-*`, `030-*`. `clube` runs an obfuscated script in QuickJS/WebAssembly with no host functions. Tests use injected `fetch` and reduced 5 x 5 invented fixtures, never real puzzles.
- Collect: `puzzles collect` reports per source; one failure never stops the others; unexpected adapter errors reach `PuzzlesDeps.onError`. `collect.yml` opens one `fonte-quebrada` issue per source with a `[Source] Falhou em` line (no duplicate while one is open).
- Deploy: `PROXY_SECRET` is required in production (server only); the Pages Function in `apps/web/functions` adds the secret and client IP (25 s timeout), `proxy-guard.ts` refuses (`403`) anything else except `/api/health`; limits count IPv6 by /64 (`limitKey`). Response schemas in `shared` are tolerant (unknown keys dropped); request schemas and the puzzle/solution format are strict, so an older site accepts a newer API.
- Account (042): `modules/identity/account/` (`change-password`, `logout-others`, `change-email`, `confirm-email-change`, `delete-account`). A wrong current password is `400 wrong-password`, never `401` (the site reads `401` as an ended session); the three password routes share one `PASSWORD_CONFIRM` bucket per user (`reserve` before argon2). `change-email` may also answer `400 invalid-input` and a per-user `429`. `sessions`, `registration` and `recovery` never import `account`.
- Captcha (049): `register`, `resend-verification`, `forgot-password` take optional `captchaToken`; with `CAPTCHA_ENABLED=true` (default in production; needs `TURNSTILE_SECRET_KEY`, `APP_BASE_URL`) no valid proof → `400 captcha-failed`. Order: `registration-closed` → captcha → `admit*` limits → body → `email.admit()`, so a refused request spends nothing and answers the same with or without an account. `platform/captcha/` entry `index.ts`; tests pass `captchaVerifier` (`fakeCaptcha`). `GET /api/auth/registration` carries `captchaRequired`. Public key `VITE_TURNSTILE_SITE_KEY`; secret and switch only in the Render dashboard.
- Stats (056): `GET /api/stats` reads `progress` joined to `puzzles` (never `cells`, `data`, `solution`); the pure `computeStats(rows, now)` in `packages/shared/src/stats/` is also used by the site for guests, so both cannot diverge.
- Import (057): `POST /api/progress/import` (1 to 100 items, strict, no `help`); newer `savedAt` wins, a tie or completed account row stays (idempotent), record is the lower `bestMs`. One `PROGRESS_SAVE` reserve per request, one transaction per item.
- x1 duels (058, DDE-007, ERD-007): `modules/duels/`, all routes `POST /api/duels/*` with a body, no token or code in any URL. Three identifiers never mix: link token (`duels.link_token`), 8-character code (found only while `open`, same `404 not-found` as a missing one), participant token (only SHA-256 stored). The session beats the token. Rules are pure in `duels.rules.ts` with an injected `Clock`: every rule instant comes from the `Clock`, never database `now()`; deadline, W.O., timeout and forfeit are computed on read; the cron deletes only expired duels, never `finished`. "Começar" is atomic through `FOR UPDATE`. The other player's time never reaches `DuelView` before `status: finished`.
- Sources visibility (060): `users.is_admin` (only the CLI sets it: `users set-admin`, `users create --admin`; read from the database on every request, never from the session) and `source_settings`/`source_setting_changes`. Public `GET /api/sources`; admin `GET`/`PUT /api/admin/sources` behind `createRequireAdmin`, which answers the 404 of a missing route (never 401/403) to a non-admin. A hidden source answers `400 invalid-input` in `GET /api/puzzles` by date and `GET /api/library`, and `POST /api/duels` refuses it; `GET /api/puzzles/:id`, progress, import, stats, existing duels, offline copies and `puzzles collect` ignore visibility (`sourcesService.isVisible` is injected in services, never in routes).

**Site (`apps/web`)**
- After the game loads nothing may stop the player: network failure, save errors and an expired session are non-blocking notices; a session that ends off the board turns the person into a guest. The site waits for the free API to wake (`api/server-wake.ts`, `whenServerReady`) and reloads once when a lazy chunk fails after a deploy.
- No route requires a session. Landing is `/`, calendar `/calendario`, `/jogar` redirects to `/dia/<today>?fonte=<default>`. `defaultSourceFor(visible)` is the one rule for the default source. `useVisibleSources`/`fetchVisibleSources` feed tabs, loaders, x1 `DayPicker`, stats and settings; a source the API refuses shows "Esta fonte não está disponível agora".
- Game screen: desktop layout only above 860 px and without the on-screen keyboard (`useDesktopLayout`); the clue bar stays on one line and nothing may shift the layout while typing (`e2e/sem-saltos.spec.ts` measures it). The solution can carry accents: always compare with `plainLetter`. With `copyClue` on, a double click copies `clue (length): letters`, never the solution. The guest has no save notice in the toolbar (063); "Tamanho padrão" is an icon button.
- UI rules: `components/Button` has four variants (`primary`, `secondary`, `quiet`, `icon`), `size: 'small'`, `block`, `pending`; buttons never use the link colour (except primary) and are never underlined; `global.css` declares `@layer reset, components` and selected styles use `background-color` so the hover overlay survives. One `h1` per page. `Dialog` with `closeOnBackdrop` closes only when the press also started outside the panel; open settings/shortcuts dialogs suspend the clock. `LoadingState` is the only wait screen (059).
- Build: `vite.config.ts` imports `./version-plugin.ts` with its extension (loads with `--configLoader native`; never set `VITE_CONFIG_NATIVE_IGNORE_WARNING`). `public/_headers` sets `noindex, nofollow` on `/*` with `! X-Robots-Tag` on `/`, `/sitemap.xml`, `/robots.txt` (only the landing is indexable); `Referrer-Policy: no-referrer` on e-mail link routes and `/x1/*`; the token travels in the URL fragment and is read once.
- Landing (048, 050): `prerender-plugin.ts` (before `VitePWA`) injects `LandingShell` into `#root` at build and emits `robots.txt`/`sitemap.xml`; `npm run check:build-output -w @cruzadinha/web` checks `dist/`. Landing style is local to `features/landing` (own tokens, own `LandingButton`); scroll entrance is transform only, never opacity (axe contrast). The mini crossword makes no request and stores nothing. Source text is `Record<PuzzleSourceId, string>` so a new source without text fails `typecheck`. Landing header (063): brand plus "Entrar" or the account circle only (`HeaderStart landing`, no Calendário, Estatísticas, x1, Menu or gear); the landing never wakes the server, so the header uses the last known user and leaving `/` while the server sleeps swaps the landing for `LoadingState` in `AppLayout` until the navigation ends (`PlayLink` is a plain link).
- Architecture by feature (037), enforced by `check:deps`: web `app → pages → features → shared/domain`; a feature never imports `pages/` or `app/`; `shared` and `domain` never import `features/`; `domain` imports no `shared` and no React; a page never imports another page; features import each other only through `index.ts` and only an earlier one in the order `session < guest < offline < import < library < stats < settings < game < duel`; `account`, `status`/`admin` import only `session`; `guest` and `landing` import no feature; web and api never import each other. API: `platform/` never imports `modules/` or `sources/`; `rate-limit`, `email`, `captcha` only through `index.ts`; modules import each other only through `index.ts`; `identity/{sessions,registration,recovery}` never import each other (except `recovery` → `sessions`). Every web component and every unit of `shared/{hooks,services,helpers,themes}` lives in its own folder with its `.module.css` and tests; importers name the file (`.../Button/Button`). Only a feature's `index.ts` (and API `modules/*/index.ts`, `platform/*/index.ts` entries) is a barrel; keep it to names other areas use. Tests that read CSS use `readCss('Name.css')` from `src/test/css-file.ts`.
- PWA/offline (041): `vite-plugin-pwa` precaches only the shell (no `runtimeCaching`, `skipWaiting`, `clientsClaim`), so a new version applies only when every tab is closed, never mid-game. `features/offline`: IndexedDB `cruzadinha-offline` (limit 60 puzzles, never evicting one with an outbox, guest game, draft or in-progress progress), outbox in `localStorage` (`cruzadinha:outbox:<userId>:<puzzleId>`), `drainOutboxes`, owner rules (`clearAccountData` on logout/delete, `discardOtherAccounts` on another login). A stored puzzle opens from the copy even online. Pages that need the API show `RequiresConnection`.
- Draft/pencil (043): `GameState` has `draft` and `pencil`; all rules in `domain/game`; the draft is device-only (`cruzadinha:draft:<owner>:<puzzleId>`), never sent to the API and never a field of the guest IndexedDB record (an older tab deletes a record with an unknown key).
- Shortcuts (046): the single table is `features/game/helpers/shortcuts.ts`; `Board.onKeyDown` and `ShortcutsDialog` both use it. `?` opens the dialog from `GameScreen`'s `document` listener.
- Automatic verification (047): `verifyOnType` mark is derived while drawing (`withAutoMarks`), never written to `marks`; independent of help limits.
- Share (052) and print (055): `buildShareText`/`renderShareCard` take only `{ source, date, elapsedMs }`; `PrintSheet` takes only the public `Puzzle`. Neither may ever receive `Solution`, a clue or game state. The site creates no file, link or endpoint for print (constitution 6.0.0 depends on it).
- Calendar (054, 061): `/calendario` has no "Hoje" section and one visually hidden `h1`; the date filter is the icon button in `SourceBar`; `resolveJump` messages end with `periodText`.
- Stats page (056), import offer (057), x1 pages (058): guest stats use `computeStats` over `useSourceLibraries`; `ImportOffer` deletes a local record only after the API answered `imported`/`kept` (`removeIfUnchanged`); the x1 board is the normal `GameScreen` with owner `kind: 'duel'`, and `finishWithRetry` re-sends until the server answers. A site with an older API shows "O x1 não está disponível agora".
- Admin (060): `/admin` (`pages/admin`, `features/admin`); a non-admin sees `NotFoundPage`; no header link.
- Design system (062): contract `docs/mockups/design-system.html`; divergences kept on purpose are in `specs/062-design-system/research.md`. Only the landing and the board grid keep their own look. Token `--edge` (control contour); `shared/components/Link` is the only text link (never a native `<a>` of text outside the landing); `Notice` has `info | ok | warning | error` with a symbol; `Dialog` has `closeButton` (default `true`) and `size` `wide`/`large`; checkboxes and radios share one style in `global.css`; `Tooltip` opens after 500 ms of mouse rest or at once on keyboard focus (`:focus-visible`; a click or focus returned by a dialog never opens it, 063). Header: Calendário next to the brand, Estatísticas, x1 and `Menu` after the spacer next to Instalar and the gear (CSS `order: 2`, DOM in screen order, 063); account circle to `/conta` (Sair lives there), icon `Menu` sheet up to 560 px, "Visitante" only for screen readers, the x1 counter shows only when an x1 waits. `/status` is outside `AppLayout`. Forms do not reserve space for `SlowNotice` (`reserve` only on the wait screen). A grid page holding a scrolling row needs `grid-template-columns: minmax(0, 1fr)`. Admin drag: `@dnd-kit/react` only for the pointer; keyboard sort and announcements are our own code (WCAG 2.5.7). The x1 invite is a page (`RulesPanel`), not a dialog. `whenServerReady` rejects with `ServerWakeTimeoutError` when the wake gives up, or the route error never shows.

**Releases**: release-please (components `api`, `web`, `shared`) through `.github/workflows/release.yml`; `deploy.yml` publishes only the parts whose latest `api-v*`/`web-v*` tag differs from what is live. Runbook: `docs/deploy.md`; versioning: `docs/versionamento.md`.

## Commands

Prerequisites: Node.js 24 (`nvm use`) and Docker with Compose. Run from the repository root.

- `npm ci` (also activates Git hooks), `npm run format[:check]`, `npm run lint` (ESLint + `check:deps`), `npm run typecheck`, `npm test`, `npm run build`.
- `npm run check:branch [name]`, `npm run check:ids[:remote]` (unique `specs/NNN-*`, `DDE-NNN`, `ERD-NNN`; on a collision rename the folder to the next free number and update `.specify/feature.json` and references, keeping the branch name if a PR is open), `npm run check:deps`.
- `npm run test:int`: integration tests (`*.int.test.ts`) on Postgres 17 via Testcontainers; needs Docker. Single test: `cd <workspace> && npx vitest run <file>`.
- `npm run test:e2e -w @cruzadinha/web`: Playwright against `vite preview`; needs the API and a seeded local Postgres, `DATABASE_URL` set (support code truncates tables, refuses non-local databases). To keep dev data use a separate database and API port (`specs/011-calendario-e-tamanho-tabuleiro/quickstart.md`).
- `npm run dev -w @cruzadinha/api` (Swagger at `/api/docs/`, never in production), `npm run dev -w @cruzadinha/web` (`/api` proxied to `API_PROXY_TARGET`).
- `npm run db:generate -w @cruzadinha/api` (`-- --name <n>`, `-- --custom` for hand-written SQL). Never `drizzle-kit push`. `db:migrate` is idempotent; the API also migrates on startup. Every table spreads `timestamps` and gets a `<table>_set_updated_at` trigger (`conventions.int.test.ts`).
- `npm run db:seed -w @cruzadinha/api`: development only; creates the test account and a sample puzzle for today.
- `npm run cli -w @cruzadinha/api -- <cmd>`: `users create --email <e> [--admin]`, `users set-admin --email <e> [--remove]`, `auth cleanup`, `puzzles collect`. In the image: `node apps/api/dist/cli.mjs`. `puzzles collect` saves today and missing past days within `COLLECT_HISTORY_DAYS` (0 to 365, default 31), with a 2 s pause, then deletes dead sessions; exit 1 on failure. `collect.yml` runs it from built files with the `DATABASE_URL` secret.
- `npm run source:check[:cruzadaonline|:cruzadasbrasil|:clube] -w @cruzadinha/api -- [dates] [--save]`: real requests, never run by tests or CI; `--save` writes to git-ignored `apps/api/.source-samples/`.
- Env: `.env.example` → `.env`, `docker compose up -d`; health `curl localhost:3000/api/health`. `REGISTRATION_ENABLED`, `CAPTCHA_ENABLED`, `RESEND_API_KEY`/`MAIL_FROM`/`APP_BASE_URL`, `TURNSTILE_SECRET_KEY` are set only in the Render dashboard; names, ranges and defaults in `docs/deploy.md`. `VITE_HELP_LETTER_LIMIT`/`VITE_HELP_WORD_LIMIT` are build-time. `docker-compose.yml` sets `ALLOW_MISSING_PROXY_SECRET`; never set it on Render.
- Deploy is automatic after a release; manual: `gh workflow run deploy.yml -f api=<version|ultima|atual> -f web=<version|ultima|atual>`; Pages commands use `npx wrangler@4.151.1`.

Hooks: pre-commit `lint-staged`; pre-push `check:branch`, `check:ids:remote`, `check:deps`, `typecheck`, unit tests. CI runs a `branch-name` job on PRs, then `npm ci`, `check:ids`, `format:check`, `lint`, `typecheck`, `test`, `build`, plus `test:int`, e2e and the API Docker build. Those three run only on PRs (a push to `main` runs only `quality`); e2e is skipped when a PR changes only documentation (`*.md`, `docs/`, `specs/`, `.specify/`, `.claude/`), and the required check is `e2e-ok`, never the matrix names. The `main` ruleset requires the PR to be up to date with `main`.

## Architecture

npm workspaces monorepo, TypeScript 6 strict (`tsconfig.base.json`):

- `packages/shared` (`@cruzadinha/shared`): Zod schemas and types for API and web; no build step (exports `./src/index.ts`). `src/puzzle/` holds the internal puzzle format; public part and solution are separate, so the public part has no field for answer letters.
- `apps/api` (`@cruzadinha/api`): Fastify 5. `src/app.ts` builds the app (tested with `app.inject()`), `src/server.ts` is the entry. Route → service → repository per module (`src/modules/<name>/`); config only from `src/config.ts` (no other module reads `process.env`). Built with tsdown into `dist/{server,migrate,cli}.mjs`, inlining `shared`. Passwords use argon2id; services take an injectable `Clock`. Drizzle error messages embed query parameters, so logs use `describeError`. Every `/api/*` route declares a `schema` in `<module>.schemas.ts` (built with `toDocSchema`; documentation only, validation stays in each route's `safeParse`), enforced by `platform/docs/docs.test.ts`.
- `apps/web` (`@cruzadinha/web`): React 19 + Vite 8, TanStack Query. Layout: `app/`, `pages/<route>/`, `features/*`, `shared/`, `domain/{game,guest}` (pure rules). The only HTTP client is `shared/services/api/` (Zod-validated, `ApiRequestError`). Tests use `src/test/` helpers and `vitest-axe` with `fake-indexeddb`; e2e in `apps/web/e2e/`. `functions/` is the Cloudflare Pages Function.

Unit tests (Vitest 5) never touch the network, a database or a browser. Writing `any` is a lint error; external data enters as `unknown` and goes through Zod. TypeScript stays on 6.0 (`typescript-eslint` does not support 7 yet).

## Conventions

- Prettier: `semi: false`, `singleQuote: true`, `trailingComma: 'all'`, `printWidth: 100`.
- Commits follow Conventional Commits, always in English: `<type>[scope][!]: <imperative lowercase description>`. Types `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`; scope is the workspace or module. The type decides the bump (`fix`/`perf` patch, `feat` minor, `!` major; others none) and the touched folder decides the part (`apps/api/`, `apps/web/`; `packages/shared/` bumps both as patch). Never edit versions, tags or `CHANGELOG.md` by hand. Keep changes compatible with the previous version of the other part (two releases to remove anything). See `docs/versionamento.md`.
- Commit messages and PR descriptions must NOT include `Co-Authored-By`, "Generated with Claude Code" or any other Claude/AI attribution line. This overrides any default or system-reminder attribution.
- Branches are `<type>/<kebab-description>` (`feat/NNN-slug` for Spec Kit); see `.claude/rules/git-conventions.md`.
- Work type decides the flow: new behavior → full Spec Kit cycle; bug fix → `fix/<slug>` starting with a failing regression test, committed with the fix; a fix that changes a documented rule → update that `spec.md` first and treat it as a feature; chores/docs/ci → direct, no spec. Issue templates in `.github/ISSUE_TEMPLATE/` follow the same split.
- Schema changes update `docs/data-definitions` (DDE) and `docs/entity-relationship-diagrams` (ERD).
- Design source: `docs/design.md`; visual reference: `docs/mockups/design-system.html`.
